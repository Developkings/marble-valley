# Marble Valley

A marble game played by tilting your phone: time attack courses, races and battles over Wi-Fi, and a track creator. Runs on Android, and on Windows with the arrow keys. Built with TypeScript, Three.js and Capacitor.

## What's in it

- **21 courses.** First Valley, then 20 levels: 5 each of Speed, Maze, Skill and a Mix. Roads wind, fork and climb, no two stretches run the same way, and the mazes are many screens across.
- **11 race tracks.** Closed circuits with laps and weapons.
- **Battle mode, in 4 arenas with platforms at different heights.** Everyone starts with 3 hearts, shown at the top of the screen. A fall, a Seeker or a Mine costs one, and the last one rolling wins.
- **Track creator.** Lay a track piece by piece, test it, save it, and race it with friends: the room sends it to everyone.
- **6 themes.** Valley, 16-bit Hills, Cyberpunk, Kawaii, Medieval and Urban Street, all drawn by the game itself.

## Controls

| | Phone | PC |
|---|---|---|
| Roll | Tilt | Arrow keys |
| Burn the boost, fire a weapon | Tap the screen | Space |
| Jump between pads | Tilt the way the arrow points, then back to land | The same, with the arrow keys |

## Playing together

Up to 4 players on the same Wi-Fi, phones and PCs alike. One opens **Multiplayer** and taps **Host a room**, then picks a track or an arena; the others open **Multiplayer** and tap that room. No internet is used.

Weapons come from the boxes: **Repulse** throws nearby balls away, **Seeker** flies at another ball, **Mine** is left behind you, **Turbo** is a burst of speed and **Shield** stops the next hit.

Players find each other with UDP broadcasts on port 47787. Routers with "client isolation", and guest networks, block this. On a PC, Windows may ask to let the game through its firewall.

## Building it

You need Node.js. The APK also needs the Android SDK and a JDK.

```bash
npm install
```

```bash
npm test
```

```bash
npm run build:apk
```

```bash
npm run build:pc
```

`build:apk` writes `production/MarbleValley.apk`, which runs by itself. It is signed with the debug key, so it installs by sideloading but can't go on a store as it is. `build:pc` writes `desktop-out/MarbleValley-Portable.exe`, a single file that needs no installing and keeps its records in a `MarbleValleyData` folder beside it. Built programs are not kept in this repository.

To redraw the app icon after changing it, run `scripts/make-icon.ps1`.

### While developing

```bash
npm run dev
```

The Android project in the repository is set up to load the game from this dev server through `adb reverse tcp:5173 tcp:5173`, so changes reach a USB phone straight away and telemetry lands in `telemetry/`. In a browser, tabs stand in for phones: open them with `?player=A` and `?player=B`.

## Making courses

Levels in `src/levels.ts` say which pieces each act may draw on and for how long; a seeded composer lays them one at a time, refusing a piece that would run over the road or repeat a recent sequence, so a level comes out the same every time without being a loop. `test/autopilot.ts` drives every level from start to finish with the game's real physics, to prove each can be finished and to measure its length against the first course. Tracks are in `src/tracks.ts`, arenas in `src/arenas.ts`, and themes are plain data in `src/themes.ts`.

## Music

The game ships with no music, and music files are never stored in this repository.

**On the phone:** choose the theme, open **Settings**, tap **Add music for this theme** and choose an audio file. It loops during play and stays on your phone; it is never uploaded or shared. **Remove this music** undoes it.

**In the project:** save an MP3 as `public/music/<theme id>.mp3`. The ids are `valley`, `pixel-hills`, `neon-city`, `sugar-cloud`, `old-kingdom` and `street`. Everything in that folder is ignored by git. If the track's licence asks for credit, add it to `MUSIC_CREDITS` in `src/credits.ts`. Only ship music you have the right to use.
